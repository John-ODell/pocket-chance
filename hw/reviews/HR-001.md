# HR-001: Review of DR-001, module layout under lib/ and games/

- **Verdict: fits**
- Reviewer: microcontroller expert, 2026-10-03. Numbers from `hwtest/ram_free.py`, `hwtest/board_info.py`.

## Numbers
- Free RAM after the framebuffer: **104,192 bytes**, largest block 83,980 (`hw/BUDGET.md`).
- Importing a module costs RAM for its bytecode and objects. Modules of the size described (a driver, a font table, a rules module) run roughly 2–10 KB each (estimate; I will measure the dev's real files once uploaded). Twelve modules ≈ 40–60 KB, leaving ~50–60 KB in play plus whatever the game module itself holds.
- Flash: trivial. Code for the whole project is well under 200 KB against 1.39 MB free today.

## What the dev must stay inside
1. **Import a game only when chosen, and release it on exit**, exactly as proposed. Do `del sys.modules['games.blackjack']` (or the module name used) and `gc.collect()` on leaving, or the memory is not actually returned.
2. **Create the framebuffer once, at start, before anything else large.** The largest block shrinks as the heap fragments (84 KB largest out of 104 KB free right after the framebuffer). A 115 KB allocation made late may fail even when `gc.mem_free()` says there is room.
3. Keep the font table in flash, not RAM, if it is large: either a `bytes` literal (MicroPython keeps bytes literals in the .mpy/code object, but on the stock build they still load into RAM when the module imports), or read glyphs from a file. The monolith's string table is small enough not to matter.
4. **Confirmed on the board:** `sys.path == ['', '.frozen', '/lib']`. `/lib` imports work with no setup; `/games` is not on the path, so `main.py` must add it (`sys.path.append('/games')`), or import as `games.blackjack` with a `/games/__init__.py` (an empty file; MicroPython needs it for package imports from `/`). Either works; the second needs one more file for John to upload.
