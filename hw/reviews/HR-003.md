# HR-003: Review of DR-003, byte order of converted pixels

- **Verdict: fits** (code analysis agrees with the dev; the visual confirmation on the panel is running now and this file gets one line added when John answers)
- Reviewer: microcontroller expert, 2026-10-03. Script `hwtest/byteorder.py`.

## What I checked
1. **The dev's reading of the old driver is correct.** `colour(r,g,b)` in `main_monolith.py` puts the 5 red bits and the top 3 green bits in the low byte (`r = rp*8`, green bits 3–5 of `gp` land in bits 0–2) and the low 3 green bits and 5 blue bits in the high byte (green → bits 13–15, `b = bp*256` → bits 8–12). `framebuf.RGB565` stores the low byte first. `spi.write(buffer)` sends memory in order. So the panel receives `RRRRRGGG GGGBBBBB`: **big-endian RGB565**, which is what an ST7789 expects with `0x3A = 0x05`. The "BRG" label in the Waveshare example is the same byte swap, misdescribed.
2. **Consequence for the file format:** a file that holds big-endian RGB565 is copied into the framebuffer unchanged and goes down the wire unchanged. No swap loop. The dev's Option A is right and is also the fastest possible path (measured 4.4–5.6 MB/s `readinto`, `hwtest/flash_read.py`).
3. **Consequence for drawing primitives:** every colour passed to `fill_rect`, `text`, `pixel` and the blit key must be the **byte-swapped** value, as `colour()` already produces. Pure red for `framebuf` is `0x00F8`, not `0xF800`. The transparent key `F8 1F` on disk is the number `0x1FF8` to `blit()`, as the dev says.
4. **Visual test is on the screen now.** `hwtest/byteorder.py` fills the left half with the bytes `F8 00` and the right half with `00 F8`, writes "TOP" along the top edge and "L" at the left. If the **left half is red**, item 1 is confirmed. If the right half is red, the dev flips one line in the converter and `colour()` in the old driver would have been wrong all along (it is not; the old program showed correct colours for years). "TOP" at the top and "L" on the left confirm the orientation under `0x36 = 0x70`, which settles the open question in DR-003 and DR-006.

## What the dev must stay inside
- Files: big-endian RGB565, no swap on load.
- All colour constants in code: byte-swapped form (`0x00F8` red, `0xE007` green, `0x1F00` blue, `0xFFFF` white, `0x0000` black). Provide one `rgb(r,g,b)` helper and never write raw 565 literals in game code.
- Blit key: `0x1FF8`.
