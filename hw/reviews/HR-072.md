# HR-072: Review of DR-072, the main menu's look (three code-drawn styles)

- **Verdict: A fits; C fits; B fits with limits (the side strips as designed do not).** John has ruled A; the built menu gets its own numbers when it lands.
- Reviewer: microcontroller expert, 2026-10-04. `hwtest/menu_style_bench.py` draws each option's primitive mix on the real LCD (step-1n `lib/`, 62.5 MHz SPI, `machine.freq` clock) since no menu code exists yet: shade strips, borders, pills with `ellipse` ends, suit signs, plaque, size-2 labels, bulbs, band and `show_rect` pushes, cream panels with mini cards.

## Reading
- The dev's estimates miss that **size-2 text is the menu's cost**, not the shapes: three labels ≈ 43 ms today and in every style. Style A's entry at 111 ms is the same class as today's menu with the photo (92–124 ms), and its joystick move (41 ms) is a little faster than today's (45–63 ms) because the shade strips are cheaper than the photo rows. Both are one-off, user-paced events: **fits**.
- Style B's chase as specified does not fit: `show_rect` for a 12 × 240 column is 43 ms, so the four edges cost ~96 ms per step out of 150, 64 % of the loop with the panel never quiet. Top and bottom bands alone (5.5 ms, 3.7 %) are fine; the sides would have to be pushed as part of a full `show()` (18 ms; whole step 23 ms, 15 %) or the chase confined to the top and bottom. Either way the menu loop stops idling, which is the battery cost DR-072 names; the PCB's standby figures will be measured, not promised, so a never-idle menu is the wrong default screen. **B fits with limits**: top/bottom bands only, or a full `show()` per step, and the chase stops after a few seconds of no input.
- Style C at 66 ms fits; `poly` was not benched (the fan was approximated with offset rectangles), so add ~1 ms per card for it.

## Limits for the built style A
1. Keep the row band as the unit of redraw on a joystick move (two bands, ~41 ms); do not redraw the title band on a move.
2. Entry is one full redraw + `show()`; ~110 ms is the number to beat or match when the built menu is benched. If the dev wants it faster, the size-2 labels are the only lever (they are 40 % of it) and they are a design constant, so leave it.
3. No buffers, no files beyond the icon sheet (as built today); RAM at the menu must stay at 68.2 KB after gc (HR-066's figure on the same build).
4. The 15-shade gradient's 1 px banding is a taste item for John, not a hardware one.

## Not measured
The built menu (not written); `poly`; John's eyes on the colours.
