## What it does
`play()` gains `except Exception as e: game_error(...)` around `mod.run(ctx)`. `game_error()` collects garbage, prints the traceback over USB, writes `modname: traceback` to `/error.log` (overwritten each time), saves the bankroll, shows a three-line message for 4 s and drops the presses made meanwhile. The existing `finally` (drop the module, release sheets, collect, re-open the icons sheet) still runs, so the menu comes back in its normal state.

## Checks
| Point | Finding |
|---|---|
| Catches `MemoryError` | Yes: `MemoryError` is an `Exception` subclass in MicroPython. `KeyboardInterrupt` is not, so `hwtest/peek_port.py` (Ctrl-C to find where a program sits) keeps working |
| Handler allocates after a `MemoryError` | `gc.collect()` runs first; MicroPython tracebacks hold (file, line, name) triples, not frames, so the game's objects are free by then. The handler then needs a few hundred bytes (format strings, a file object): fine |
| File write guarded | `try/except Exception: pass` around the log, and again around the save, so a filesystem error cannot raise out of the handler |
| Message fits the panel | Size-1 text is 8 px wide: "caribbean stopped: MemoryError" is 30 characters = 240 px, exactly the width, so it starts at x = 0 and the last glyph touches the right edge. Fits; one character longer would clip. A shorter type name or `modname[:9]` would give margin, not required |
| `help()` sub-module | If the error happens inside `caribbean_pay.show()`, `caribbean_pay` stays in `sys.modules` (the game's own `del` is skipped); about 1 KB until the next collect of an unreferenced module... it is referenced by `sys.modules`, so it stays until the game is next entered and `help()` drops it. Cosmetic |
| Behaviour change for a working game | None: the `try` body is unchanged; the `except` clause costs nothing until it fires |

## Does it mask or help the HR-F06 theories?
- **It cannot mask a panel stall.** A stalled ST7789 raises nothing, so the handler never runs; the screen stays as it was, just as now. What it adds is a **record**: after any future freeze, an absent or stale `/error.log` proves no exception was involved, and a fresh one names the line. That is exactly the evidence the dev's theory and mine were missing, so it sharpens the diagnosis either way. Note that if the panel has stalled, the 4 s message itself will not be visible; the log and the save still happen.
- **Neutral for the SPI-speed trial.** The trial runs the real program from the mount with the panel clock lowered; this branch neither helps nor hinders it. The two can be combined in one live session.
- **Saved-balance test (HR-F06), sharpened by the dev:** in the flop state the Ante is only *displayed* as taken; the bankroll changes at settle. So after a freeze, `/save.json` unchanged = the A press never registered; changed = the showdown ran and the panel stalled. A PUSH (dealer fails to qualify, about one hand in three) leaves the balance unchanged either way, so a single frozen hand can be ambiguous; two freezes, or a non-push hand, settle it.
